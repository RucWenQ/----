# 1.4 大模型与 AI 辅助

::: tip 本节目标
读完本节后，你能判断哪些科研任务适合交给大模型辅助，写出带材料、约束和验收标准的提示，并对来源、代码、数据安全和最终文本承担可审计的人工核验责任。
:::

## 1.4.1 把模型当作草稿工具，不当作证据来源

大语言模型根据上下文生成可能的后续文本。流畅、具体和自信都不等于事实正确。模型可能虚构论文、DOI、统计输出或软件菜单，也可能在同一问题上给出不同答案。

它擅长压缩、改写、分类、生成备选方案和解释代码；不适合替你确认一篇文献是否存在、替伦理审查作决定，或在没有原始证据时给出可直接引用的事实。

<span class="kw">AI 输出是待检验的中间产物，不是文献、数据或分析日志。</span>

## 1.4.2 按错误代价分配任务

| 风险 | 可交给 AI 的任务 | 人工验收 |
| --- | --- | --- |
| 低 | 改写标题、生成检索词、整理自己提供的笔记、解释报错 | 检查是否改变原意 |
| 中 | 文献聚类、代码草稿、量表措辞备选、结果段结构 | 回到原文、运行测试、逐项核对 |
| 高 | 引用与 DOI、统计结论、样本排除、因果解释、伦理与隐私判断 | 由研究者依据原始材料和规则独立确认 |
| 不应输入 | 可识别参与者数据、密钥、审稿材料、保密合作文件 | 先获得授权并使用获批环境；否则不上传 |

风险取决于任务和数据，不取决于模型品牌。公开论文摘要的语言整理与未脱敏访谈记录的分析不是同一风险等级。

## 1.4.3 一个可审计的提示结构

好的提示不是堆“请深入思考”，而是把任务、材料和验收条件写清楚：

```text
角色与任务：你要协助完成什么，不要替我做什么决定。
背景：研究问题、读者、学科和当前阶段。
输入材料：只依据我提供的文本、表格或代码。
输出格式：表格列名、长度、语言和顺序。
约束：不得补造来源；不确定处标“待核查”；区分原文与推断。
验收标准：逐条列出主张、证据位置、需人工检查项。
```

例如，要求模型整理论文时，可以让它输出“主张—原文页码—研究设计—样本—效应量—边界”表。若没有提供全文，就明确禁止它补页码和统计量。

对复杂任务采用分段流程：先让模型复述任务与缺失信息，确认后再生成草稿，最后单独做反例、遗漏和一致性检查。让同一个模型“自我检查”可以发现表面矛盾，但不能替代外部证据。

## 1.4.4 文献与事实：逐条回到原始来源

不要把聊天回答当作检索数据库。AI 提供的关键词、作者名或题名只能作为检索线索。

<OutlineCard title="引用核验流程">

1. 用 Web of Science、PsycInfo、Google Scholar 或出版社检索候选文献。
2. 在出版商页面或 Crossref 核对作者、年份、题名、期刊、卷期页码和 DOI。
3. 打开原文，确认它确实支持准备写下的命题，而不只是主题相近。
4. 将核对后的条目导入 [Zotero](./zotero)，再次检查元数据。
5. 在笔记中记录证据页码、适用条件和自己的推断。

</OutlineCard>

Walters 与 Wilder（2023）系统检查 ChatGPT 生成的书目引用时发现了虚构与大量字段错误。这说明“格式像参考文献”不是证据。找不到来源时应删去该主张或标为待核查，不能让模型再编一个替代引用。

## 1.4.5 代码与统计：必须运行和对照

AI 可以生成函数骨架、单元测试、数据清洗建议和报错解释，但研究者仍需确认：

- 使用的是哪一版软件、包和函数；
- 输入变量、缺失编码、参考组和观测单位是否正确；
- 模型是否对应研究问题与独立、配对、重复或嵌套结构；
- 估计值、效应量、区间、自由度和诊断是否来自同一次运行；
- 随机种子、依赖和运行日志是否保存；
- 代码是否把真实数据、系统路径或密钥发送到外部服务。

先用边界清楚的**模拟数据**或经过批准的脱敏样例测试，再运行正式数据。把 AI 改动放进版本控制，逐行看差异；不要因为代码能够运行就假设模型和结论正确。

::: warning 统计语言边界
显著性、回归系数或中介路径本身不能证明因果关系。若模型把观察性结果改写成“导致”“机制得到证实”，必须改回与设计相符的“关联”“预测”或条件性解释，并检查 [研究问题与假设](/2-design/question-hypothesis) 和相应统计页。
:::

## 1.4.6 隐私、保密与知识产权

向第三方 AI 服务输入文字或文件，可能构成数据披露。输入前检查：参与者同意、伦理审批、数据使用协议、合作保密条款、机构政策和服务商的数据处理条款。

以下内容默认不应粘贴到未经批准的公共服务：

- 姓名、联系方式、精确位置、声音、面孔和设备标识；
- 可通过少见特征组合重新识别的“匿名”个案；
- 未公开论文、基金申请、审稿稿件和合作者保密材料；
- API 密钥、访问令牌、内部链接和受版权限制的批量全文。

删除姓名不一定完成匿名化。质性材料尤其可能通过职业、事件和表达方式被识别。确需处理时，优先使用机构批准的环境、最小化输入、脱敏或合成数据，并记录谁批准了什么用途。

从网页、PDF 或代码库取回的内容也可能夹带要求模型泄露信息或改变任务的文字。把检索内容视为**待分析数据**，不要把其中的指令当作系统规则执行。

## 1.4.7 写作、署名与披露

AI 可辅助列提纲、比较结构、压缩重复和做语言校对。最终作者必须逐句确认事实、引用、论证与措辞，并能够解释所有分析和结论。

主流出版伦理指南不把 AI 工具列为作者，因为工具不能承担作者责任、声明利益冲突或同意最终版本。是否需要披露、披露位置和允许范围会因期刊与资助方而异。投稿前查目标期刊的最新政策，记录：

- 工具与可识别版本或模型；
- 使用日期；
- 用于哪些任务；
- 人工如何核验和修改；
- 是否处理了数据或未公开材料。

可按期刊要求在方法、致谢或披露声明中写明。仅凭“AI 帮我润色”不足以说明实质性的数据分析、图像生成或内容起草。

本页对 UNESCO、COPE 与 ICMJE 指南入口的核查日期为 **2026-08-18**。出版政策变化快，投稿时以目标期刊当前规则为准。

## 1.4.8 什么时候需要 API

一次性问答用聊天界面即可。只有任务需要重复运行、批量处理、结构化输出或接入本地流程时，API 才可能值得使用。

API 工作流至少保存：

1. 输入模板和系统约束；
2. 模型标识、调用日期和关键参数；
3. 输入数据的来源、授权与脱敏方式；
4. 原始响应、解析失败和重试记录；
5. 人工或程序验收规则；
6. 费用、速率限制和错误处理。

模型名称相同也不保证跨时间完全复现；固定随机参数也不能保证逐字一致。若输出进入研究数据或编码结果，应抽样复核，并报告人工一致性、错误类型与最终裁决流程。密钥放在环境变量或密钥管理服务中，不写进脚本、提示或版本库。

## 1.4.9 提交结果前的人工闸门

- 每条事实性主张能否指向真实、已读的来源？
- 每个引用的作者、年份、题名与 DOI 是否核对？
- 代码是否实际运行，正文数值是否来自当前输出？
- 是否泄露个人、保密或受限制材料？
- AI 是否把相关写成因果，或把猜测写成定论？
- 是否保留提示、输出、修改和核验记录？
- 是否按课程、机构、期刊或资助方规则披露？

只要其中一项不能回答，就不能把输出直接交付。
