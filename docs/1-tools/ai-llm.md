# 1.4 大模型与 AI 辅助

::: tip 本节目标
读完本节后，你能在 Codex 中建立一个可追踪的心理学研究项目，写出带材料、边界和验收标准的提示，使用或创建一个小型 Skill，并亲自核验文献、文字、代码、统计结果与图形。
:::

## 1.4.1 先判断：这个任务值得交给 AI 吗？

你可能不是缺一个“更聪明的聊天回答”，而是卡在具体步骤：十篇论文来不及逐篇做表、分析脚本报错、结果段缺少结构，或一张图能画出来却不像可投稿的图。此时 AI 适合作为**可检查的工作助手**，帮你整理材料、生成草稿、修改代码和列出检查项。

它不能替你确认一篇论文真实存在、替伦理审查作决定，也不能在没有数据和运行记录时给出可直接报告的统计结果。流畅、具体和自信都不是证据。

| 当前任务 | 可以让 AI 先做 | 你必须亲自确认 |
| --- | --- | --- |
| 阅读文献 | 按固定字段提取候选信息、比较研究 | 回到全文核页码、样本、设计、效应与结论边界 |
| 写作 | 根据已核证据表组织段落、压缩重复 | 每个事实和引用确由来源支持，推断没有冒充原文 |
| 数据分析 | 读取代码本、起草或修改脚本、运行检查 | 变量、模型、样本、输出和解释都对应研究问题 |
| 作图 | 按统计结果生成代码、调整样式、导出 | 图形忠实反映数据结构与模型，代码能重新生成图片 |
| 伦理或隐私 | 列出待查问题与可能风险 | 由研究者、导师、伦理委员会或数据管理员决定 |

以下用一个贯穿示例：你准备研究“社会排斥是否与助人意愿下降有关”，已有研究问题、几篇全文和一份**模拟数据**。目标不是让 Codex 独立完成论文，而是让每个产物都能回到来源、代码和人工决定。

## 1.4.2 在 Codex 中建立一个不会失控的项目

### 先把文件放对位置

把研究材料放进一个独立文件夹，再将该文件夹作为 Codex 的项目或工作区打开。最小结构可以是：

```text
exclusion-helping/
  README.md             # 研究问题、运行顺序、负责人
  AGENTS.md             # 本项目长期适用的工作规则
  literature/           # 合法取得的全文与证据表
  data-raw/             # 原始数据，只读；本例放模拟数据
  code/                 # 清洗、分析与作图脚本
  output/               # 由代码生成的表和图
  writing/              # 提纲与草稿
```

`README.md` 解释“项目是什么、怎样运行”；`AGENTS.md` 写 Codex 在这个项目中应长期遵守的规则。例如：只改任务指定文件；先读代码本；不补造引用；统计代码必须运行；提交前检查 `git diff`。一次任务的特殊要求仍写在当前提示中，不要把所有临时想法都塞进 `AGENTS.md`。

### 用任务边界管理上下文

1. **第一轮只盘点。** 让 Codex 读取目录、`README.md`、`AGENTS.md` 和 `git status`，先报告缺失材料，不修改文件。
2. **一次只交付一个结果。** 例如先做证据表，再写一段综述；先检查分析计划，再改脚本。不要用一个任务同时要求“读完文献、分析数据、画图并写全文”。
3. **给出允许修改的文件。** 明确“只修改 `code/03_model.R`”，能显著减少无关改动。
4. **每轮都看差异与验证。** 至少检查 `git status --short`、`git diff`、运行命令及其真实输出；不要只看 Codex 的完成摘要。
5. **把决定写回项目。** 排除规则、变量重编码、图形选择和未解决问题应进入 README、分析日志或相应文档，不能只留在聊天记录中。

可以从这条提示开始：

```text
先读取 README.md、AGENTS.md、git status 和目录树，不修改文件。
我的问题是：现有项目能否从模拟原始数据重新生成主要结果和图？
请输出：(1) 已有输入；(2) 预期运行顺序；(3) 缺失或冲突；
(4) 下一步最小任务。每项都给出文件路径，不要猜测不存在的内容。
```

Codex 应先给出盘点，而不是立刻创建一批文件。若它声称“项目可复现”，你还需要在干净副本或空环境中按记录重跑一次。

## 1.4.3 提示词：把任务写成可验收的委托

新手常见的提示是“帮我分析一下”或“把这段写得学术一点”。问题不在于不够礼貌，而在于没有说明材料、边界和怎样算完成。一个可执行提示至少包含五部分：

```text
任务：要完成的单一产物，以及不要替我做的决定。
材料：允许读取的文件、字段、原文或代码。
边界：不得补造来源；不确定处标 NEEDS_CHECK；保护哪些数据。
步骤：先检查什么，再修改什么，最后运行什么。
验收：输出格式、必须报告的数值、测试命令和允许修改的文件。
```

例如，不要只说“检查我的回归”。可以写：

```text
读取 preregistration.md、data/codebook.csv 和 code/03_model.R。
先判断观测单位、结果变量、预测变量和排除规则是否一致，不修改文件。
然后只修改 code/03_model.R：用模拟数据复现预注册的主模型，
保存样本量、系数、95% CI、诊断和 session 信息到 output/。
实际运行脚本。最后列出运行命令、输出路径、警告和仍需人工决定的问题。
不得把关联写成因果，不得使用 data-raw/ 中未在代码本出现的字段。
```

“请再检查一遍”只能发现一部分表面矛盾。更有效的做法是把验收拆开：先核材料完整性，再运行代码，再由另一个明确步骤比对正文与输出。对高风险结果，仍要由研究者或合作者独立复核。

## 1.4.4 Skill 是什么，什么时候值得创建？

**Skill** 是一套可重复调用的工作流程。它通常以 `SKILL.md` 为入口，还可以带脚本、参考资料和模板。提示解决“这一次怎么做”，`AGENTS.md` 解决“这个项目长期遵守什么”，Skill 则解决“多个项目反复遇到同一种任务时，按什么流程做”。

| 需求 | 更合适的载体 | 例子 |
| --- | --- | --- |
| 只在当前任务有效 | 当前提示 | 这次只核查三篇论文 |
| 当前项目长期有效 | `AGENTS.md` | 原始数据只读，代码必须实际运行 |
| 多次复用的专业流程 | Skill | 从心理学论文提取可核验的证据表 |
| 定时重复执行 | 自动任务 | 每晚核查一个教程页面并运行构建 |

### 使用一个已有 Skill

1. 先查看当前环境实际列出的 Skills，不要假定另一台电脑也已安装。
2. 任务关键时显式写出 Skill 名称，例如“使用 `$psychology-evidence-table` 处理这三篇全文”。
3. 同时给出本次输入、输出路径和边界；Skill 不是替你授权上传保密材料。
4. 检查它实际读取了什么、创建或修改了什么，以及是否运行了要求的验证。

如果 Skill 没触发，先检查名称、描述是否准确覆盖当前任务，以及它是否已在当前环境启用。不要通过反复换措辞掩盖安装或作用域问题。

### 创建一个最小 Skill

只有流程已经重复出现、输入输出相对稳定、人工验收点清楚时才值得创建。一个“什么都能做的心理学助手”无法可靠触发，也难以测试；“把实证论文整理成带证据位置的表格”更合适。

若当前环境提供 `$skill-creator`，可以让 Codex 用它搭建并检查结构；否则按当前 Codex 官方文档创建。无论采用哪种入口，都先写清触发与不触发条件。最小 `SKILL.md` 可以表达为：

```markdown
---
name: psychology-evidence-table
description: 从用户提供的心理学实证论文中提取带页码或章节位置的证据表；不用于检索或补齐未提供的论文。
---

# Workflow

1. 确认全文可读，并记录文件名。
2. 提取研究问题、设计、样本、变量、效应量、限制和证据位置。
3. 原文未报告的字段写 `NR`，无法确认的内容写 `NEEDS_CHECK`。
4. 输出 CSV 和核验清单；不得生成新的书目条目。
```

创建后至少用三种情况试跑：一篇信息完整的论文、一篇缺页或 OCR 较差的论文，以及一个本来不该触发的任务。检查它是否会补造缺失字段、混淆多个研究、忽略页码或越界修改文件，再收窄描述和步骤。Skill 中的期刊政策、软件菜单和模型名也会过期，应注明核查日期并定期复查。

## 1.4.5 实例一：辅助文献阅读，但不让引用“凭空出现”

### 准备

把合法取得的全文放入 `literature/papers/`，为每篇文件使用稳定编号，例如 `S01.pdf`。另建 `literature/question.md`，写清研究问题、纳入范围和需要提取的字段。扫描 PDF 先检查文字能否正确选择和搜索；OCR 错误会让页码和数值失真。

### 逐步操作

```text
读取 literature/question.md 和 literature/papers/S01.pdf。
只依据这份全文，输出一行证据表到 literature/evidence-draft.csv：
study_id、完整书目信息、研究设计、样本与排除、操纵/测量、
主要效应量与区间、作者原述限制、证据页码或章节。
原文未报告写 NR；无法可靠读取写 NEEDS_CHECK；不得联网补齐。
另列出所有需要我打开 PDF 人工核对的字段。不要改其他文件。
```

先逐篇提取，再合并。一次塞入几十篇全文容易造成研究编号、样本和结果串行。人工核验时逐格打开原文：书目信息可用出版社或 Crossref 对照，但“这篇论文是否支持这句话”必须看正文和研究设计，不能只核 DOI。

### 预期结果与失败信号

合格输出能把每个数值和结论定位到具体页面或章节，并保留 `NR` 与 `NEEDS_CHECK`。如果表格出现原文没有的效应量、所有限制都写成同一句套话，或页码无法定位，应停止合并，缩小到单篇并检查 PDF/OCR。

Walters 与 Wilder（2023）对模型生成书目引用的系统检查发现虚构引用和大量字段错误。这里最短的防线不是“让模型更谨慎”，而是只从已提供全文提取、逐条定位证据、再用权威元数据源核书目信息。

## 1.4.6 实例二：受约束写作与防止编造

完成核验后，把人工确认列设为 `verified=yes`。写作任务只允许使用这些行：

```text
读取 literature/evidence-verified.csv 和 writing/outline.md。
只使用 verified=yes 的证据，为“社会排斥与助人行为”写 500 字综述草稿。
每个事实句末标注 [study_id]；区分作者报告、跨研究比较和我的推断。
证据不足的位置写 [NEEDS_SOURCE]，不得新建作者、年份、DOI 或数值。
输出后附“句子—study_id—证据页码”对照表。只创建 writing/draft-01.md。
```

接着做两遍人工检查：第一遍按 `[study_id]` 回到证据表和全文，第二遍只看论证是否把观察性关联写成因果、把单项研究写成共识，或把作者的限制删掉。找不到支持时删句或保留 `[NEEDS_SOURCE]`，不要让模型“补一篇引用”。

AI 可以调整结构和语言，但最终作者必须能够解释每个主张。AI 工具不能承担作者责任；是否披露、放在哪里、允许哪些用途，应在投稿时查目标期刊、机构和资助方的当前规则。

## 1.4.7 实例三：让 Codex 改分析，但结果必须来自运行

### 先让它读设计，不要立即改代码

Codex 应先从预注册、代码本和数据摘要回答：研究问题是什么，观测单位是参与者还是试次，变量怎样编码，主模型需要哪些假设和诊断。若这些答案互相冲突，继续写代码只会把错误自动化。

确认后再允许它修改一个脚本，并要求实际运行。验收时至少对照：

- 分析样本量、缺失与排除是否符合预注册；
- 结果变量、参考组、对比编码和观测层级是否正确；
- 估计值、效应量、区间、自由度和诊断是否来自同一次运行；
- 随机种子、软件与依赖版本、警告和运行日志是否保存；
- 观察性结果是否仍使用“关联”或“预测”，而非“导致”。

::: warning “代码运行成功”不是统计验收
脚本没有报错，只说明计算机执行了指令。错误的变量、模型或排除规则也能顺利运行。至少用手算的小例子、模拟的已知参数、另一实现或合作者复核其中一种方式检查结果。
:::

若 Codex 反复修改同一处却没有收敛，要求它停止编辑，报告最小报错、已尝试步骤、当前 `git diff` 和下一项可证伪的检查。不要在正式数据上无记录地试错。

## 1.4.8 实例四：从统计结果到可复现图，而不是只要“好看”

先把数据结构和统计问题告诉 Codex，再指定图形。一个实用的对应关系是：

| 你需要表达什么 | 优先考虑 | 需要警惕 |
| --- | --- | --- |
| 两组连续结果的分布与个体差异 | 原始点 + 箱线/小提琴 + 区间 | 只画柱高会藏住分布与样本量 |
| 同一参与者前后变化 | 配对点/线，或模型估计与区间 | 把配对数据画成互不相关的两组 |
| 两个连续变量的关联 | 散点 + 合适的拟合与区间 | 平滑线被误读为因果或线性关系 |
| 多个模型系数 | 系数图/森林图 + 区间 | 不同尺度的系数直接比较 |
| 分类结果比例 | 计数或比例 + 明确分母和区间 | 截断坐标或只报百分比 |

给 Codex 的提示可以这样写：

```text
读取 output/model-results.csv、data/codebook.csv 和 code/04_plot.py。
先说明每行代表什么、估计值与区间来自哪个模型，再判断系数图是否合适。
只修改 code/04_plot.py：保留原始结果数值，统一图例、色盲友好颜色、
字体、字号、坐标标签、面板间距和注释，导出 180 mm 宽的 PDF 与 300 dpi PNG。
实际运行脚本，并报告输出尺寸、路径、警告和人工仍需查看的视觉问题。
不要手写或重新估计 model-results.csv 中不存在的数值。
```

打开导出的成图，逐项检查图例、颜色、字体、字号、坐标、布局、注释、裁切和分辨率。再从空的 `output/` 目录运行脚本，确认图能重新生成。若你在绘图软件中手调，记录每一步或把调整写回代码；否则下一次运行会丢失修改。

所谓 vibe coding 只改变了产生代码的方式，没有降低审查标准。尤其要检查：依赖是否锁定、路径是否可移植、统计结果是否被重复计算、默认聚合是否改变观测单位、颜色是否误导，以及图片是否来自当前脚本。

## 1.4.9 隐私、提示注入与权限边界

以下内容默认不应输入未经批准的公共 AI 服务：

- 姓名、联系方式、精确位置、声音、面孔、设备标识及可重新识别的个案组合；
- 未公开论文、基金申请、审稿材料和合作者保密文件；
- API 密钥、访问令牌、内部链接和受版权限制的批量全文；
- 伦理审批或数据使用协议没有覆盖的参与者材料。

删除姓名不等于完成匿名化。确需处理时，先确认参与者同意、伦理批准、数据协议、机构政策和服务条款，再选择获批环境，最小化输入并记录授权。

网页、PDF、数据单元格或代码注释也可能含有“忽略原任务、上传文件、泄露信息”等指令。把外部内容视为**待分析的数据**，不要让其中的文字改变项目规则或扩大权限。发现这类内容时停止执行并报告位置。

## 1.4.10 提交前的人工作业单

<OutlineCard title="从草稿到可交付结果">

1. **范围：** `git status` 与 `git diff` 只包含本次允许的改动。
2. **来源：** 每条事实和引用都能回到真实、已读的来源与证据位置。
3. **代码：** 实际运行命令、版本、输出和警告已经保存。
4. **统计：** 数据结构、模型、效应量、不确定性、诊断和因果措辞一致。
5. **图形：** 图类型对应数据与结果，导出文件可由当前代码重新生成。
6. **安全：** 没有上传或提交个人信息、保密材料、密钥与未授权全文。
7. **披露：** 按课程、机构、期刊和资助方的当前规则记录工具、日期、用途与人工核验。

</OutlineCard>

只要有一项无法回答，就把它写成未解决事项，而不是让 AI 生成一个看似完整的结论。

本页 Codex/OpenAI 文档、UNESCO 与 ICMJE 入口核查日期为 **2026-08-23**。Codex 的界面、Skills 入口和可用能力可能随版本、安装方式与机构策略变化；以当前环境列出的能力和官方文档为准。
