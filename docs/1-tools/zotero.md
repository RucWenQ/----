# 1.2 Zotero 全工作流

::: tip 本节目标
读完本节后，你能把一篇论文可靠地收进 Zotero，检查并整理元数据与附件，在 Word 或 LibreOffice 中插入可自动更新的引文，并为个人或团队文库建立同步和备份规则。
:::

## 1.2.1 先理解 Zotero 管理的对象

Zotero 不是“装 PDF 的文件夹”，而是一套以**书目条目**为中心的资料库。一个条目可以连接 PDF、网页快照、笔记、标签和相关条目；同一条目还可以同时出现在多个分类中，而不产生副本。

| 对象 | 用途 | 最低检查 |
| --- | --- | --- |
| 条目 | 保存作者、题名、年份、期刊、DOI 等元数据 | 条目类型、作者顺序、年份、题名、DOI |
| 附件 | PDF、网页快照或其他文件 | 是否对应正确版本，能否打开 |
| 分类 | 按项目或主题组织条目 | 一篇文献可进入多个分类 |
| 标签 | 标记主题或处理状态 | 少量、稳定、团队含义一致 |
| 笔记 | 记录摘要、方法、判断和待办 | 写清自己的判断与原文位置 |

<span class="kw">引文能否正确生成，取决于条目元数据，不取决于 PDF 文件名是否漂亮。</span> 导入后先校对条目，再开始做笔记和引用。

## 1.2.2 安装与抓取

基础组合是 Zotero 桌面端、对应浏览器的 Zotero Connector，以及文字处理器插件。文字处理器插件通常随桌面端安装；若工具栏没有出现，可按官方故障排查页重新安装，而不是手工复制插件文件。

### 从文献落地页抓取

1. 打开论文在期刊、数据库或预印本平台的**条目页**，不要只打开裸 PDF。
2. 点击 Connector 图标，确认保存到正确分类。
3. 等待附件下载结束，再打开条目检查元数据。
4. 若抓取失败，优先用 DOI、ISBN 或 PMID 的“通过标识符添加条目”；最后才手工录入。

数据库导出的 RIS 或 BibTeX 适合批量导入，但导入后仍要检查。不同数据库可能把在线发表年份、卷期年份、文章编号、页码或团体作者处理得不同。

### 每次导入的六项检查

- **条目类型**：期刊论文、书籍章节、预印本和会议论文不要混用；
- **作者**：姓名拆分正确、顺序正确，团体作者使用单字段模式；
- **题名**：删除数据库附加的全大写或无关标记，但不要擅自改写原题名；
- **出版信息**：年份、期刊、卷、期、页码或文章编号一致；
- **稳定标识符**：优先保留 DOI；网址仅保留有意义的落地页；
- **版本**：记录引用的是预印本、在线优先版还是正式出版版。

::: warning 不要从 PDF 猜元数据
从裸 PDF 自动识别很方便，但扫描件、补充材料和旧论文容易识别错误。识别后应回到出版商页面或 Crossref 等书目来源核对，不能把自动结果直接当成定稿。
:::

## 1.2.3 用项目流程组织，而不是追求复杂分类

一个够用的个人文库可以只有三层：

```text
项目名/
  01-reading
  02-core
  03-cited
```

分类表示“这篇文献在哪些项目中使用”；标签更适合表示跨项目属性。建议把标签分成两类：

- 内容标签：例如 `moral-judgment`、`social-identity`；
- 状态标签：例如 `to-read`、`read`、`verify`。

不要同时维护十几套颜色、星级和状态。规则越复杂，越容易在忙时失效。可保存“高级搜索”来动态查看“某项目中尚未阅读”或“没有附件”的条目。

### 一条可复用的阅读笔记

每篇核心文献至少记录：

1. 它回答什么问题，主要结论是什么；
2. 样本、观测单位、设计和关键变量；
3. 主要估计值、不确定性与关键分析；
4. 最强证据与最重要的边界；
5. 它与你的研究问题有什么关系；
6. 需要回到原文核对的页码、图表或补充材料。

摘要不是笔记的替代品。引用原句时标出页码，并把“作者声称什么”与“你如何判断”分开写。

## 1.2.4 附件、同步与备份

Zotero 同步包含两部分：**数据同步**负责条目、笔记和标签，**文件同步**负责附件。启用其中一项不代表另一项也已完成。关联文件（linked files）不由 Zotero 文件同步管理，团队使用前应先确认每台设备都能解析一致路径。

个人文库至少保留三层：

1. Zotero 账号同步，用于多设备数据同步；
2. 本机定期备份完整 Zotero 数据目录；
3. 另一位置的版本化或离线备份，用于应对误删、磁盘损坏和同步传播错误。

::: danger 不要这样备份
不要在 Zotero 运行时把它的活动数据目录直接放进普通网盘的实时同步文件夹。数据库文件被两个同步程序同时修改时可能损坏。按 Zotero 官方备份说明复制完整数据目录，并在恢复前退出 Zotero。
:::

组文库适合团队共享条目、笔记和附件。建立前约定：谁拥有组、谁能编辑、附件由谁维护、如何命名状态标签，以及项目结束后谁负责归档。涉及未公开材料或受版权限制的附件时，还要确认共享对象和许可边界。

## 1.2.5 在 Word 或 LibreOffice 中引用

标准流程是：

1. 在文档中选择引用样式；
2. 用 **Add/Edit Citation** 插入条目，需要时补页码或前后缀；
3. 用 **Add/Edit Bibliography** 生成参考文献表；
4. 元数据或样式变化后点击 **Refresh**；
5. 交稿前在文档副本中做最终检查。

不要手工修改自动生成的参考文献。手改内容可能在刷新时消失；应回到 Zotero 条目修正元数据。若期刊要求纯文本，最后在**另存的交付副本**中使用 Unlink Citations。解除链接不可逆，工作主文档应保留字段代码。

引文样式由 CSL 文件控制。先在 Zotero Style Repository 搜索期刊样式，再对照期刊最新作者指南抽查作者列举、年份后缀、题名大小写、DOI 和参考文献排序。样式名称正确不等于当前投稿要求一定完全匹配。

## 1.2.6 从检索到投稿的固定流程

<OutlineCard title="每篇文献的处理流水线">

1. 从数据库或出版商落地页抓取条目与附件。
2. 对照原始来源检查六项元数据，并合并重复条目。
3. 放入项目分类，添加少量主题与状态标签。
4. 阅读后写结构化笔记，关键引文标页码。
5. 在文字处理器中通过 Zotero 插件插入引文。
6. 交稿前刷新并抽查正文引文与参考文献表。
7. 完成同步状态检查，并按计划备份数据目录。

</OutlineCard>

出现重复条目时使用 Zotero 的 Duplicate Items 视图合并，避免直接删除其中一条而丢失分类、笔记或已链接的引文。团队成员批量改元数据或移动附件前，先同步并保留可恢复备份。

## 常见故障

| 现象 | 先检查什么 |
| --- | --- |
| 浏览器按钮保存成网页 | 是否位于文献落地页；Connector 与桌面端是否更新并连接 |
| Word 中没有 Zotero 工具栏 | 桌面端设置中的文字处理器插件是否已安装；重启文字处理器 |
| 引文显示错误 | 条目类型和元数据是否正确；样式是否选对；是否已 Refresh |
| 另一台电脑只有条目没有 PDF | 文件同步是否启用；附件是否为关联文件；存储空间与同步错误日志 |
| 同一篇文献出现多次 | 在 Duplicate Items 中合并，不要仅凭相似题名批量删除 |

本页的软件入口与官方说明核查日期为 **2026-08-18**。菜单名称可能随版本变化，遇到差异以 Zotero 官方文档为准。
