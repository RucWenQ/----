# 1.7 网络与 VPN

::: tip 本节目标
读完本节后，你能区分机构登录、图书馆代理与 VPN 的用途，理解 VPN 的加密和隐私边界，按最小权限连接学术资源或研究环境，并系统排查常见访问故障。
:::

## 1.7.1 先判断你究竟要访问什么

“网页打不开”可能是网络、身份认证、资源许可、浏览器状态或服务故障。先确认目标，不要一遇到问题就安装来源不明的代理软件。

| 目标 | 优先入口 | 原因 |
| --- | --- | --- |
| 公开论文、开放数据或软件文档 | DOI、出版社开放页面、机构知识库 | 不需要机构网络 |
| 学校订购的数据库或全文 | 图书馆数据库导航、机构登录 / CARSI、图书馆代理 | 由学校身份和许可授权 |
| 校内系统、实验室服务器或受限存储 | 机构官方 VPN 或获批远程接入 | 进入受控网络前需要认证和安全策略 |
| 与合作者传文件 | 机构批准的存储或项目平台 | 便于权限、审计和版本管理 |

先从学校图书馆官网进入资源，确认机构确实订购、账号状态正常且访问方式受支持。数据库能打开但某一期刊全文不能下载，可能是订购范围问题，不一定是 VPN 故障。

<span class="kw">网络可达、身份已认证和内容有许可，是三件不同的事。</span>

## 1.7.2 四个容易混淆的概念

| 概念 | 做了什么 | 没有保证什么 |
| --- | --- | --- |
| **机构联合认证** | 在资源方页面跳转到学校身份系统，认证后返回授权结果 | 不把整台设备接入校园网 |
| **图书馆代理** | 让受支持的数据库请求经图书馆代理并附带机构授权 | 通常只覆盖配置过的学术资源 |
| **VPN** | 在设备与 VPN 网关之间建立受保护的网络隧道，并按策略转发流量 | 不自动获得数据库许可，也不等于匿名 |
| **远程桌面 / SSH** | 在授权下操作校内电脑或服务器 | 不代表可以把受限数据下载到个人设备 |

CARSI 是中国教育科研计算机网环境下的联邦认证基础设施。是否能用、覆盖哪些资源以及账号开通方式，以本校图书馆和信息化部门当前说明为准。

本页机构与安全入口核查于 **2026-08-19**。VPN 客户端、登录地址、订购数据库和许可条款变化较快，不在教程中固化具体菜单；操作时使用学校官网的最新说明。

## 1.7.3 VPN 的安全边界

VPN 主要保护**设备到 VPN 网关**这一段传输，并让部分或全部流量从该网关发出。流量离开网关后，仍应依靠 HTTPS、SSH 等端到端协议保护。VPN 服务运营方或机构也可能依据政策记录连接时间、账户、设备或流量元数据。

因此，VPN 不提供以下保证：

- 不保证匿名，也不会消除浏览器账号、Cookie、设备指纹和下载记录；
- 不会让 HTTP 自动具备端到端保密性；
- 不会修复感染恶意软件、过期系统或泄露密码的设备；
- 不会把违反许可、伦理审批或数据使用协议的行为变成合规行为；
- 不会自动备份文件，也不是团队协作平台。

NIST SP 800-46 Rev. 2 建议把远程接入作为整体安全体系管理，包括受管设备、认证、补丁、访问控制和日志，而不是只安装一个客户端。

### 全隧道与分流

- **全隧道**：设备的大部分网络流量都经机构网关。策略一致，但可能更慢，也会让个人流量进入机构网络边界。
- **分流**：只有指定网段或资源经 VPN，其他流量直接上网。性能通常更好，但路由、DNS 和本地网络暴露更复杂。

采用哪种模式由机构配置决定。不要自行修改路由、证书或安全策略来绕过限制；若目标资源未被正确转发，把资源域名、时间和错误信息交给技术支持。

## 1.7.4 一个安全的连接流程

<OutlineCard title="校外访问步骤">

1. 从学校图书馆或信息化部门官网确认支持的访问方式和官方客户端下载地址。
2. 更新操作系统、浏览器和安全软件，删除不再使用的远程访问工具。
3. 使用个人账户和多因素认证；密码、动态码和恢复码不发给他人。
4. 只在需要时连接，确认客户端显示的机构、网关和证书信息正确。
5. 从图书馆数据库导航打开资源，用一篇已知可访问的文章验证权限。
6. 完成后退出数据库与 VPN；涉及受限数据时，按项目要求清除临时副本并记录传输。

</OutlineCard>

在公共 Wi-Fi 上，先完成网页认证再连官方 VPN。避免使用公共电脑处理参与者数据、保存密码或下载受限材料；个人设备也应启用磁盘加密、自动锁屏和更新。

::: danger 不要使用来历不明的“免费 VPN”或共享账号
未知服务可能读取或改写流量，客户端也可能带来恶意软件。共享机构账号会破坏审计并违反服务条款。只使用学校、单位或项目明确批准的接入方式。
:::

## 1.7.5 学术资源的许可边界

学校购买的是特定用户在特定条件下使用资源的许可，不是把数据库内容变成可任意分发的文件库。常见高风险行为包括：

- 用脚本或下载器批量抓取全文，触发平台封禁；
- 把机构订购的 PDF 上传到公开网盘、公开仓库或第三方 AI 服务；
- 将账号或校外访问凭据交给校外人员；
- 忽略数据库对文本与数据挖掘、课程包和跨机构共享的单独条款。

需要系统综述全文、文本挖掘或大批量元数据时，先查数据库许可与 API，必要时联系图书馆。文献条目的题名、作者和 DOI 与受版权保护的全文不是同一类材料；仍应按平台条款获取和使用。

处理参与者数据时还要检查 [研究伦理](/2-design/ethics)、知情同意、数据管理计划与合作协议。远程连接校内服务器，不代表可以把原始数据复制到未批准的个人云盘。

## 1.7.6 按层排查故障

不要反复重装客户端。记录测试时间、网络、目标 URL、错误文字和已经尝试的步骤，然后按层定位：

1. **本地网络**：能否打开学校官网和一个公开 HTTPS 页面？公共 Wi-Fi 是否还需要网页登录？
2. **时间与更新**：系统日期、时区和浏览器是否正确？时间错误会导致证书和多因素认证失败。
3. **账户认证**：能否登录统一身份系统？密码、账号状态或多因素认证是否过期？
4. **隧道状态**：官方客户端是否显示已连接到正确机构？是否频繁重连？
5. **路由与 DNS**：校内系统能否解析和访问？换网络后问题是否消失？不要把内部域名、IP 或日志公开发布。
6. **资源授权**：从图书馆导航重新进入；页面是否显示学校名称？换一项已知订购资源交叉测试。
7. **浏览器状态**：用私密窗口测试，清理该站点 Cookie，关闭会改写请求的扩展，但不要绕过安全警告。
8. **服务端问题**：查看学校通知或资源方状态页；若仍失败，把最小复现信息提交给支持人员。

| 现象 | 更可能的层级 | 下一步 |
| --- | --- | --- |
| 所有网站都打不开 | 本地网络、DNS 或隧道路由 | 断开 VPN 验证基础网络，再检查官方状态 |
| 校内系统可用，数据库仍要求付费 | 资源授权、代理或订购范围 | 从图书馆入口重进并核对资源范围 |
| 只有一个数据库失败 | 资源端故障、Cookie 或许可 | 测试另一数据库并记录目标 URL / 错误时间 |
| 登录后立即掉线 | 账号、客户端、网络切换或超时策略 | 更新官方客户端，固定网络并联系支持 |
| 连接后网速显著下降 | 全隧道路由、网关负载或远距离链路 | 记录时段和测速对象，按机构策略反馈 |

向支持人员提供错误截图前遮盖姓名、账号、IP、令牌和研究数据。不要在公开论坛粘贴完整 VPN 日志。
